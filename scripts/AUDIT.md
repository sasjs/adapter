# Dependency audit gate

Run `node scripts/audit-check.mjs` from a Linux checkout with Node 22 or 24, npm, curl and Python 3 available on PATH. The pull-request job runs it before `npm ci`; the publish job currently runs it after `npm ci`. Network access to the npm registry is required even for replay: bootstrap fetches exactly the manifest/lock-pinned `@sasjs/release` tarball over HTTPS, verifies its lockfile SHA-512, validates archive members and package identity, and extracts only the package manifest and entrypoint into a private temporary directory. It does not install packages or run lifecycle scripts.

Both the production (`--omit dev`) and full reports are checked at severity `info`. Production findings cannot be waived, even if the allowlist is empty. Dev exemptions live in `scripts/audit-allowlist.json`; each must name a GHSA, nonempty exact report package keys, a reason, and a `recheckBy` date. Set `devOnly: true` to document intent; the shared gate enforces production exclusion regardless. See the pinned release package README for its full schema. Stale entries fail; the list is currently empty. For a recorded report replay, run `node scripts/audit-check.mjs --audit full.json --prod production.json`; both reports are required and no audit is run, but the pinned gate is still downloaded.

The lockfile authenticates bytes only against the reviewed repository pin, not against a change that can modify both the pin and this script. Protect workflow and dependency changes through review; never provide untrusted PR code with publish credentials. The bootstrap executes the verified gate before auditing it. Registry outages, missing tools, malformed archives and integrity failures fail closed. npm's own audit also needs registry availability. Local tests may disable the unrelated Cypress binary download with `CYPRESS_INSTALL_BINARY=0`.
