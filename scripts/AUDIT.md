# Dependency audit gate

Run `node scripts/audit-check.mjs` from a checkout with Node 22+ and npm on PATH; both pull-request and publish jobs run it before `npm ci`. The bootstrap is pure Node: no curl, no Python, and no network access at all. It reads the committed `scripts/vendor/@sasjs-release-<version>.tgz`, verifies its SHA-512 against the lockfile pin before anything is extracted or executed, then extracts only the package manifest and entrypoint into a private temporary directory with a deliberately restricted ustar reader (fixed 512-byte headers, no links, no special members, no pax/GNU extensions; decompression capped at 16 MiB, 4096 members, 4 MiB per member). It does not install packages or run lifecycle scripts. Because there is no external tooling, the gate runs on every platform the adapter supports, Windows included; the pinned shared gate itself launches npm without a shell on Windows (see the release package README).

Both the production (`--omit dev`) and full reports are checked at severity `info`. Production findings cannot be waived, even if the allowlist is empty. Dev exemptions live in `scripts/audit-allowlist.json`; each must name a GHSA, nonempty exact report package keys, a reason, and a `recheckBy` date. Set `devOnly: true` to document intent; the shared gate enforces production exclusion regardless. See the pinned release package README for its full schema. Stale entries fail; the list is currently empty. For a recorded report replay, run `node scripts/audit-check.mjs --audit full.json --prod production.json`; both reports are required and no audit is run, but the pinned gate is still bootstrapped from the committed tarball.

The lockfile authenticates bytes only against the reviewed repository pin, not against a change that can modify both the pin, this script and the committed tarball together. Protect workflow and dependency changes through review; never provide untrusted PR code with publish credentials. The bootstrap executes the verified gate before auditing it. Malformed archives and integrity failures fail closed. npm's own audit also needs registry availability. Local tests may disable the unrelated Cypress binary download with `CYPRESS_INSTALL_BINARY=0`.

Vendoring note: the committed tarball is the exact registry artifact for the pinned version. When bumping `@sasjs/release`, download the new tarball from the registry URL recorded in the lockfile, place it at `scripts/vendor/@sasjs-release-<version>.tgz`, and let the lockfile integrity check verify it on every run; remove the previous version's tarball in the same commit.
